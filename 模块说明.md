## 中文

**初始化推荐在完成 OOBE（Out-of-Box Experience，Windows 首次设置）后、存入个人文件或积累应用数据前执行。** 当前代码没有 OOBE 状态检查，也没有“目录必须为空”的限制。新装阶段已有的少量内容仍会按迁移规则处理。

长期使用的系统需要先备份，再核对文件占用、软件固定路径和链接依赖。已有 UserSpace 可用“修复并更新”维护位置设置；文件会保留原位，但软件之后可能改为读取新位置。

### 文件分工

| 文件 | 职责 |
| --- | --- |
| `启动.cmd` | 用系统自带的 Windows PowerShell 打开向导，然后退出，避免启动器占用正在迁移的目录。 |
| `app/UserSpace.ps1` | 显示菜单、差异清单和确认窗口。初始化或修复成功后请求注销。 |
| `app/UserSpace.Core.psm1` | 检查目录状态，执行移动、位置修复、图标更新、结果检查和空目录清理。 |
| `app/UserSpace.Native.cs` | 调用 Windows 的目录查询、设置和同卷移动接口。 |
| `app/UserSpace.Strings.json` | 保存中英文界面文字。路径等动态内容作为参数填入文案。 |

### 目录与系统入口

工具先查询当前账户的用户目录，将其下的 `UserSpace` 作为目标。账户名、盘符和路径均在运行时获取。

Windows 为六个常用目录提供了 Known Folder 标识。文档、下载、音乐、图片和视频还有对应的 Local 标识，因此共检查 11 个系统入口。不同入口可能返回不同位置，工具会分别核对。

`Get-USInitPlan` 收集当前位置和目标位置。`Get-USRepairPreview` 将 11 个系统入口、11 个 `User Shell Folders` 值和六个 `Shell Folders` 值列入差异清单。确认期间若设置改变，修复会停止，要求重新核对。

### 初始化与修复的区别

初始化由 `Invoke-USInit` 执行。它补建 12 个预设目录，把六个系统目录中的已有内容迁入目标，再设置 Windows 目录位置。Assets 等六个自建目录只补建缺失项。

修复由 `Invoke-USUpgrade` 执行。它要求六个目标目录已存在，修正系统入口和图标。现有文件、旧目录及自建目录中的链接保留原位。软件开始使用新位置后，旧数据可由使用者单独导入。

两种操作都先检查处理范围。系统入口必须位于默认用户目录或对应的 UserSpace 目录；OneDrive、自定义重定向和相关路径上的目录链接需要单独处理。

### 文件移动与操作记录

初始化先检查同名冲突，再用 Windows 同卷移动接口迁移文件和子目录。同名目标会阻止移动，已有内容保留。子目录中的链接随目录一起移动；相对链接需要使用者另行检查目标是否仍正确。

`Save-USState` 在移动或修改设置前写入记录。记录采用临时文件替换方式，上一份完整记录保存在 `.previous` 文件中。中断后可能留下部分完成状态，记录用于判断哪些步骤已执行。

记录包含本机路径、账户标识和图标原始配置，保存在当前账户的 `%LOCALAPPDATA%\UserSpaceBootstrap`。公开分享前需要脱敏。工具没有自动回滚或用户文件备份功能。

### 位置设置与旧式兼容值

`Set-USKnownPath` 调用 Windows 的 `SHSetKnownFolderPath`，分别设置常用和 Local 入口。对应的 `User Shell Folders` 配置由系统接口更新。

部分旧式 `Shell Folders` 值可能仍保留原路径。`Sync-USShellFolderCache` 先检查其余 38 项，全部通过后，再保存并更新六个常用兼容值。写入前会复查系统位置，写入后会重新读取结果。其他注册表值保留原样。

查看状态和清理空目录只读取这些位置。位置设置只在确认初始化或修复后执行。

### 图标与显示名称

文件夹的位置和图标配置相互独立。`Write-USFolderMetadata` 从 Windows 的目录定义中读取图标与显示名称，保存原 `desktop.ini` 的字节和属性，再更新图标配置。

工具给目标目录自身添加 ReadOnly 属性，以启用资源管理器的显示定制。目录内的用户文件保持原有属性。配置更新后会发送刷新通知，最终界面仍应在重新登录后检查。

### 结果检查

`Invoke-USFreshVerification` 启动新的 Windows PowerShell 进程。新进程执行 44 项检查：

| 检查内容 | 数量 |
| --- | ---: |
| 常用和 Local Known Folder 位置 | 11 |
| `User Shell Folders` 和 `Shell Folders` 配置 | 17 |
| 旧式目录接口和 .NET 返回的位置 | 10 |
| 目标目录的图标配置及属性 | 6 |

工具核对检查进程的账户、版本和结果数量，并验证程序文件是否仍与本次运行一致。如果工具随 Downloads 迁入 UserSpace，会在新位置寻找完整程序。

这些检查覆盖系统返回值和图标配置。实际软件是否使用固定路径，以及资源管理器如何显示入口，仍需在真实账户中验证。

### 清理与注销

`Get-USCleanupPlan` 检查原来的六个物理目录。目录为空，或只剩已识别的 `desktop.ini` 时，才列为可清理项。确认后，`Invoke-USCleanup` 再次核对系统位置，保存残留图标配置，并用非递归方式删除空目录。新出现的文件会阻止删除。

初始化和修复的确认窗口会提前提示自动注销。全部检查通过后，界面调用 `shutdown.exe /l` 请求注销当前账户。命令使用普通注销，应用有机会提示保存。取消、失败、查看状态和清理均不会触发注销。

### 语言

`Set-USLanguage` 根据 Windows 显示语言选择简体中文或英语，也接受主窗口中的手动选择。选择仅在本次运行中有效，并传给检查子进程。

`Get-USText` 从本地 JSON（JavaScript Object Notation，一种文本数据格式）字典读取文案，使用编号占位符填入路径和检查结果。字典内容作为文本处理。系统目录名、注册表值名和检查字段保持稳定，切换语言只影响显示文字。

开发测试使用临时目录和模拟的系统设置，覆盖文件移动、清理边界、独立进程检查及注销条件。此类测试无法替代真实系统上的重定向和应用兼容性测试。

## English

**Initialize after Windows first-run setup (OOBE, Out-of-Box Experience), before adding personal files or accumulating application data.** The code checks neither OOBE status nor whether the folders are empty. It applies the migration rules to any content already present, including files created during initial setup.

For an established system, back up first and review locked files, app-specific fixed paths and link dependencies. Repair and update maintains an existing UserSpace setup while keeping files in place. Apps may start reading the updated locations afterward.

### Files and responsibilities

| File | Responsibility |
| --- | --- |
| `启动.cmd` | Opens the wizard with Windows PowerShell, then exits so the launcher does not hold a folder open during migration. |
| `app/UserSpace.ps1` | Displays the menu, differences and confirmation dialogs. Requests sign-out after successful initialization or repair. |
| `app/UserSpace.Core.psm1` | Checks directory state and handles file moves, location repair, icon updates, verification and empty-folder cleanup. |
| `app/UserSpace.Native.cs` | Calls Windows interfaces for folder queries, location updates and same-volume moves. |
| `app/UserSpace.Strings.json` | Contains Chinese and English messages, with placeholders for paths and other runtime values. |

### Folders and Windows locations

The tool queries the current account's profile directory and uses its `UserSpace` subfolder as the target. It obtains the account name, drive and paths at runtime.

Windows provides Known Folder identifiers for the six common personal folders. Documents, Downloads, Music, Pictures and Videos also have Local identifiers, making 11 locations to check. Different identifiers can return different paths, so the tool checks each one.

`Get-USInitPlan` collects current and target locations. `Get-USRepairPreview` compares 11 Windows locations, 11 `User Shell Folders` values and six `Shell Folders` values. If settings change while you review the list, repair stops and asks you to review the updated differences.

### Initialization and repair

`Invoke-USInit` creates missing folders from the 12 presets, moves existing content from the six Windows folders, then sets their Windows locations. It creates the other six presets, such as Assets, only when missing.

`Invoke-USUpgrade` requires the six target folders to exist. It updates folder locations and icons while leaving files, old folders and links in custom folders in place. You can import old data as needed after apps start using the new locations.

Both operations check the permitted scope first. Windows locations must point to the default profile folders or their matching UserSpace targets. OneDrive, custom redirection and directory links along relevant paths need separate handling.

### File moves and operation records

Initialization checks for name conflicts before using the Windows same-volume move interface. An existing destination blocks the move and preserves its content. Links inside a subfolder move with that subfolder; check relative links afterward to confirm that they still point to the intended targets.

`Save-USState` writes a record before each move or settings update. It replaces records through a temporary file and keeps the previous complete record in a `.previous` file. An interruption may leave part of the operation complete; the record helps identify completed steps.

Records contain local paths, account identifiers and original icon metadata. The tool stores them in `%LOCALAPPDATA%\UserSpaceBootstrap` for the current account. Redact them before sharing. The tool provides neither automatic rollback nor backups of your personal files.

### Location settings and legacy compatibility

`Set-USKnownPath` calls Windows `SHSetKnownFolderPath` for the common and Local identifiers. The Windows interface updates the corresponding `User Shell Folders` settings.

Some legacy `Shell Folders` values may retain old paths. `Sync-USShellFolderCache` first runs the other 38 checks. After those pass, it backs up and updates the six common compatibility values. It rechecks Windows locations before writing and reads each result back afterward. Other registry values stay unchanged.

Status checks and empty-folder cleanup only read these locations. Location updates run after you confirm initialization or repair.

### Icons and display names

Folder locations and icon metadata are separate settings. `Write-USFolderMetadata` reads Windows folder definitions for icons and display names. It saves the original `desktop.ini` bytes and attributes before updating the icon configuration.

The tool adds the ReadOnly attribute to the target directory itself to enable Explorer customization. Files inside retain their existing attributes. The tool sends a refresh notification after the update; check the final appearance after signing in again.

### Verification

`Invoke-USFreshVerification` starts a new Windows PowerShell process to run 44 checks:

| Check | Count |
| --- | ---: |
| Common and Local Known Folder paths | 11 |
| `User Shell Folders` and `Shell Folders` values | 17 |
| Paths returned by the legacy folder interface and .NET | 10 |
| Target-folder icon metadata and attributes | 6 |

The tool checks the verification process's account, version and result count. It also verifies that the program files still match the current run. If the tool moves with Downloads into UserSpace, it looks for the complete program in the new location.

These checks cover Windows return values and icon metadata. App-specific fixed paths and Explorer's displayed entries still need testing in a real account.

### Cleanup and sign-out

`Get-USCleanupPlan` inspects the six original physical folders. It marks a folder eligible only when empty or containing a recognized `desktop.ini` alone. After confirmation, `Invoke-USCleanup` rechecks Windows locations, saves residual icon metadata and removes empty folders without recursive deletion. Newly created files prevent removal.

Initialization and repair warn about sign-out in their confirmation dialogs. After all checks pass, the interface requests current-account sign-out with `shutdown.exe /l`. It uses normal sign-out, allowing apps to prompt about unsaved work. Canceling, a failure, viewing status and cleanup do not trigger sign-out.

### Language

`Set-USLanguage` selects Simplified Chinese or English from the Windows display language or your choice in the main window. The choice lasts for the current run and passes to the verification subprocess.

`Get-USText` reads the local JSON (JavaScript Object Notation) dictionary and fills numbered placeholders with paths and results. It treats dictionary content as text. Folder names, registry value names and verification fields remain stable; language selection changes displayed messages.

Development tests use temporary folders and simulated Windows settings to cover file moves, cleanup boundaries, new-process verification and sign-out conditions. These tests do not replace real-system redirection and app-compatibility testing.
